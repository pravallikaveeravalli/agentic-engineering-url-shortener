Fix: restored `recovered.size()` as the divisor. This is precisely T119's own concern made concrete: an
MTTR calculation that silently widens its own denominator to include unrecovered rows produces a smaller,
better-looking number for the wrong reason — the unrecovered failures did not get faster to recover from,
they got averaged away. MttrCalculatorTest.handComputedMttr and MttrDenominatorTest (T119) both guard this
specific defect from two angles: the hand-computed value here, and a dedicated seeded-population proof
with the separate count asserted in MttrDenominatorTest.
