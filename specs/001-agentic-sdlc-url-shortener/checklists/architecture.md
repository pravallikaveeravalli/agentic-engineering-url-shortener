## Architecture Definition Completeness

- [ ] CHK044 — Are the system boundary, actors, external dependencies, and trust boundaries each defined explicitly rather than implied? [Now] [Completeness, Plan §1]
- [ ] CHK045 — Is data ownership stated per entity class, including which data is mutable and which is append-only? [Now] [Completeness, Plan §1]
- [ ] CHK046 — Are application-plane and control-plane responsibilities separated such that neither list contains the other's concerns? [Now] [Consistency, Plan §1]
- [ ] CHK047 — Are all seven concerns Constitution VII requires separated (domain, delivery, persistence, orchestration, policy, telemetry, infrastructure) each assigned a distinct location? [Now] [Coverage, Constitution VII]
- [ ] CHK048 — Is the dependency direction stated as a rule that can be mechanically checked, not merely as a diagram? [Now] [Measurability, Spec §NFR-MNT-001]
- [ ] CHK049 — Is every external dependency's failure mode named, with the handling for each? [Now] [Coverage, Plan §1]
- [ ] CHK050 — Is the relationship by which the control plane governs the application plane stated (subject vs import), so a reviewer can tell whether a violation occurred? [Now] [Clarity, Spec §AS-005]

## ADR Record Completeness

- [ ] CHK056 — Does every material architectural decision have an ADR, and is each decision judged *not* to need one recorded with the reason and the artifact that already decided it? [Now] [Completeness]
- [ ] CHK057 — Does every ADR contain all eleven mandated sections (Status, Context, Decision Drivers, Options Considered, Decision, Rationale, Consequences, Risks and Mitigations, Reversibility, Traceability, Validation)? [Now] [Completeness]
- [ ] CHK058 — Does every ADR's Options Considered section state, per option, approach, advantages, disadvantages, risks, implementation impact, and assessment implications? [Now] [Completeness]
- [ ] CHK059 — Does every ADR separate positive, negative, operational, testing, and governance consequences rather than listing them undifferentiated? [Now] [Completeness]
- [ ] CHK060 — Does every ADR state a reversibility assessment, and is the ordering of decisions consistent with it (lowest reversibility decided first)? [Now] [Consistency]
- [ ] CHK061 — Does every ADR name how it will be validated, by test, demonstration, or review? [Now] [Measurability]
- [ ] CHK062 — Does every rejected option carry a rejection *reason*, with no option dismissed without argument? [Now] [Completeness, Constitution VII]

## ADR Integrity & Honesty

- [ ] CHK063 — Is every ADR marked `Accepted` backed by a recorded human decision naming the deciding human and date, with none marked Accepted by the agent's own action? [Now] [Failure Path, Constitution III]
- [ ] CHK064 — Is every ADR that a human revised before accepting accompanied by a recorded revision history stating what was wrong and what changed? [Now] [Traceability]
- [ ] CHK065 — Where an argument in an ADR originated with the agent and was adopted by the human, is that provenance recorded rather than presented as the human's own? [Now] [Traceability, Constitution X]
- [ ] CHK066 — Is every ADR rationale free of circular justification (a decision justified by the fact that it was chosen, or by assessment context rather than engineering grounds)? [Now] [Clarity]
- [ ] CHK067 — Would every ADR argument survive being stated outside an assessment context, with no claim resting on "this is what is being graded"? [Now] [Clarity]
- [ ] CHK068 — Is every factual claim in an ADR one a reviewer could falsify, with no claim that is refutable in one sentence? [Now] [Measurability]
- [ ] CHK069 — Where an ADR asserts that a verification was performed, is the executed output recorded rather than the assurance that it would pass? [Now] [Failure Path, Constitution X]
- [ ] CHK070 — Does any ADR claim "applied as proposed" for a change that was only partly applied? [Now] [Failure Path, Unsupported Completion Claim]

## Architecture Drift Control

- [ ] CHK071 — Is there a defined mechanism by which an architecture change made without formal approval would be **detected**, not merely prohibited? [Now] [Gap, Failure Path]
- [ ] CHK072 — Does every change to an approved architecture, schema, contract, or workflow state have a change-control record naming owner, version impact, compatibility impact, affected consumers, tests, documentation, rollout steps, and approval? [Now] [Completeness, Spec §POL-CHG-001]
- [ ] CHK073 — Is a schema or contract change without a change-control record a **release-blocking** failure rather than an advisory note? [Now] [Failure Path, Spec §POL-CHG-001]
- [ ] CHK074 — Does the implemented structure match the documented architecture, with no undocumented drift? [Pre-Release] [Consistency, Undocumented Drift]
- [ ] CHK075 — Is the dependency-direction rule enforced by an executable check that has been demonstrated to **fail** on a deliberate violation? [Pre-Release] [Failure Path, ADR-006]
- [ ] CHK076 — Are superseded ADRs marked superseded with a reference to the record that replaced them, rather than edited in place? [Pre-Release] [Traceability]
